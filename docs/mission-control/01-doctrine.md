# Mission Control — Doctrine

## What Mission Control Is

Mission Control is a browser-based pipeline that takes a local business URL, audits it, generates two premium creative directions, and waits for human approval before anything is built or sent.

It is not a chat interface. It is not Claude Code. It is not a no-code builder.

It is an operator-grade AI pipeline that designs and builds premium websites for local service businesses — faster and better than any agency, at a fraction of the cost.

## What Mission Control Is Not

- Not a chatbot
- Not an AI code assistant
- Not a Webflow, Duda, or Wix competitor
- Not a generic "build me a website" tool
- Not a tool that builds sites without approval
- Not a tool that sends outreach without approval
- Not a tool that deploys to production without approval

## The Core Promise

Every build must do two jobs at once:

1. Make the business look more expensive, trustworthy, and modern.
2. Push the visitor toward a call, quote request, booking, or lead form.

Beautiful design that does not convert is decoration.
Conversion design that looks cheap is not enough.

## The Operating Loop

```
URL received
  → website audited
  → opportunity scored
  → two creative directions generated
  → operator approves one direction
  → build spec locked
  → executor builds
  → QA scored
  → preview generated
  → sales package drafted
  → operator approves outreach
  → outreach sent
```

Nothing moves to the next step without a human checkpoint at approval gates.

## The Two-Build Rule

Every client receives two distinct creative directions:

- **Direction A**: Safe premium. Elevated version of what the business already does.
- **Direction B**: Bold premium. Distinctive approach that makes them stand out in the market.

Neither direction is built until the operator approves one.

## Approval Gates (Non-Negotiable)

1. No build without direction approval
2. No production deploy without build approval
3. No outreach without outreach approval
4. No file deletion without explicit approval
5. No API keys in prompts

## The Executor Contract

Mission Control designs. The executor builds.

Mission Control:
- Audits the client URL
- Generates the audit object
- Routes to the correct tier
- Generates both creative directions
- Writes the locked build spec
- Sends spec to the executor
- Reviews executor output
- Scores the QA scorecard
- Generates the sales package

The executor:
- Receives the locked build spec
- Builds the website
- Returns changed files + errors
- Does not make design decisions

## The Standard

Every site delivered must feel like the business went from "old local company site" to "serious modern brand."

If it does not, it does not ship.
